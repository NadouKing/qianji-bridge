# 分支与工作目录规范

本页适用于本仓库的代码和文档维护，规则随仓库版本管理，不依赖某台电脑的父目录或旧聊天。
仅规定 Git 协作；业务权限、数据保护、验证和发布仍遵守本仓库各自的规范。

## 开始修改前

1. 阅读 `AGENTS.md` 和本次任务相关文档；检查当前路径、`git status --short`、分支、远端、
   `git worktree list` 及同需求的已有 PR。确认目录空闲，不在正在执行任务或部署服务的目录切换版本。
2. 新需求在干净且空闲的固定开发目录中，先切回主分支，再快进更新，最后新建任务分支。
   下例仅适用于已核实主分支为 `main`、远端为 `origin` 的仓库；名字不同时使用实际名称。
   **逐条执行，任一步失败就停止，不继续修改：**

   ```sh
   git switch main
   git pull --ff-only origin main
   git switch -c codex/<简短任务名>
   ```

3. 已有同需求 PR 就续用原分支：先 fetch、核对远端和主分支差异，安全同步后继续，不重复开 PR。
   断网、非快进或冲突时说明实际基线和阻塞，不强制重置，也不声称已更新。
4. 有未提交修改时先确认归属。误在主分支开始的本次工作可先建任务分支保全，再处理基线；
   混有其他工作或目录正在使用时，保留现场，使用另一个已确认空闲的工作目录。
   不覆盖无关修改，不静默 stash，不用 `reset --hard` 或 `git clean` 强行开始或收尾。

建分支不需要先 commit，也不需要空提交或占位 PR。分支不备份未提交内容：达到可说明、可安全
提交的阶段就 commit；在任务已有推送授权时 push。中断前交代未提交、未推送及验证状态，
不把密码、配置、个人或业务运行数据混入 Git。提交、推送和 PR 仍以当前任务授权为准。

## 什么时候使用 worktree

默认复用一个固定开发目录，串行切换任务分支；不要每做一次测试或审查就复制、clone 一份仓库。
确需并行开发、隔离运行目录或保护已有修改时才使用 worktree：

- 先检查已有 worktree，只有确认空闲且可用才复用，不接管其他任务的目录。
- 手动创建的目录统一放在本机选定工作根目录的 `worktrees/<项目名>/<任务名>/`，
  位于源码仓库之外；不写死盘符、用户名，不散落到桌面、下载或项目源码内。
- 主分支被其他 worktree 占用时，不强制切换：fetch 后从已核实的最新远端主分支创建任务分支。
- 工具托管的 worktree 保留在工具管理位置，使用对应管理入口归档，不手动搬动 `.git`。
- 不在多个进程或任务之间共享可写工作目录；生产执行目录沿用正式部署版本，不为开发切分支。

## 交付与退役

按本仓库要求验证并审阅 diff；获授权提交时只包含本次相关内容，PR 写明改动、验证及未验证项。
不为了凑 PR 制造无意义修改；未经用户明确要求，不合并、不发布。

提交推送后，空闲的固定开发目录可回主分支；独立 worktree 保留任务分支也可以，运行目录不动。
不能为显示“干净”而丢弃他人修改或移走仍被程序引用的运行数据。

清理前逐项核对：目录是否在用、未提交及未跟踪内容、未推送提交、合并情况，以及 Git 忽略的
配置、依赖、附件、日志、数据库、审计与恢复数据。`status` 干净、PR 关闭、目录陈旧或忽略规则
都不是单独的删除依据；压缩合并需检查实际差异，不能只查提交祖先关系。

得到清理授权后，已确认可重建且未使用的缓存可删除；需要保留的旧副本和资料先存到源码仓库外
的本地归档目录，记录原位置、归档位置、原因及恢复方式，不提交真实归档内容。
注册 worktree 使用 Git 或托管工具的正常移除/归档方式，不用文件管理器直接删除。
配置不清、仍在运行、未合并或存在无法确认归属的内容先保留并说明；不顺带删除远端分支。

## 本 fork 的远端与验证

本仓库为 `NadouKing/qianji-bridge`：`origin` 指向自己的 fork，`upstream` 指向
`fangzhengjin/qianji-mcp`。开始时仍需核对本地实际配置；上游仅作参考，同步上游属于单独任务，
不能用上游版本覆盖本 fork 的修改。

GitHub CLI 在 fork 内可能默认选择上游；查询或创建 PR 时显式指定
`--repo NadouKing/qianji-bridge`。本 fork 的日常维护向自己的 `main` 提 PR，不自动向上游贡献。
多账号环境核对实际身份与目标仓库，不为本次任务修改其他项目依赖的全局账号设置。

验证按实际修改范围选择：源码改动使用 README 指定的 Bun 版本和锁文件，运行相关测试及
`bun run typecheck`；纯文档修改检查事实、相对链接和 `git diff --check`。
测试不得连接个人生产数据库或为验证而新增真实账单。需要真实财务操作时另行取得明确授权。

本 fork 已提供账单附件 `imageUrls`，维护时保留 README 说明的详情、摘要及账号隔离边界。
服务运行说明在 README，模型使用说明在 `src/server-instructions.md`；开发规范不写入模型运行说明。
合并主分支会触发现有容器镜像构建与推送，提交 PR 不等于授权合并、发布或重启本地服务。
