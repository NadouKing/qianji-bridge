# 使用说明

本文面向通过 MCP 查询、核对或写入钱迹数据的用户与 AI 客户端。写入前应核对目标账号、金额和重复账单；失败后先查询确认状态。

## 使用要点

### 核对与写入

- 需要按账本、资产、分类、标签或成员筛选，或者写入时缺少可信 ID，才调用对应查询工具获取，不得猜测或构造 ID
- 使用 `list_bills` 批量盘点、查重或只读对账，需要完整筛选范围时继续翻页到 `nextCursor=null`，批量判断转账方向时直接读取摘要的 `fromId` 和 `targetId`，需要资产名称时只调用一次 `list_assets` 建立 ID 映射
- 列表字段无歧义时不要逐条调用 `get_bill`，只有重复或近似候选、关系冲突、摘要缺失字段或用户要求完整记录时才读取单笔详情，写入成功后直接使用写入工具返回的完整账单
- 钱迹在其他设备发生变化后，调用 `refresh_cache` 获取最新数据
- 核实多笔详情可用 `get_bills`，每次 1 至 100 个 ID，重复 ID 保留首次顺序；不存在或属于其他账号的记录返回 null，不暴露其他账号内容
- `get_bills.refresh=true` 先增量同步账单，不强制刷新全部目录；`cache.readAt` 是读取时间，`lastSyncedAt` 是本进程已知的最近成功同步时间，未知为 null，两者均为 Unix 秒
- 需要查看账单附件时，读取 `get_bill` 的 `bill.imageUrls`：按原顺序返回 HTTPS 图片读取地址，没有附件时为 `[]`；账单列表保持精简，不附带图片地址。服务返回地址，由具备图像读取能力的客户端按需下载或展示，不提供 OCR，修改附件另用专用写工具
- 创建、修改、退款、报销和删除操作会直接写入钱迹，请先确认参数

### 周期记账

`list_repeat_tasks` 直接查询当前账号的完整周期任务目录，包含暂停及结束任务，不从历史账单的来源推测设置。周期目录接口一次返回完整列表，服务不对重复返回的目录伪造分页。任务 `status=1` 表示启用，`status=0` 表示暂停；其他状态原样返回。

`create_repeat_transfer` 只创建固定金额、同币种资产间的周期转账设置，不实际申购基金或划转资金。`money` 包含 `fee`，每次转入为 `money - fee`。`repeatType=week` 时用 `weekdays` 指定星期（1 为周一，7 为周日）；`repeatType=workday` 沿用钱迹法定工作日规则，不能等同于证券交易日。`startDate` 必须是当前账号时区的未来日期，`timeOfDay` 为 `HH:mm`；不回补历史账单。

暂停或恢复用 `set_repeat_task_enabled` 传入目标 `enabled`，服务读取实际状态后决定是否调用切换接口，并回读确认。它不删除任务或既有账单。写入超时或确认失败，必须重新查询任务，不得重试整批创建或盲目再次切换。

金额随行情变化的投入不适合由固定金额任务代替实际成交。按真实付款核对本金和当笔费用；需要停止旧固定任务时先确认用户意图，保留已产生的历史账单。

### 账单附件图片

完整账单（包括写入成功后返回的账单）包含 `imageUrls`，例如：

```json
{
  "imageUrls": [
    "https://billimg.qianjiapp.com/example-image-key!webporigin",
    "https://billimg.qianjiapp.com/example-image-key_hg!huge"
  ]
}
```

以上为虚构示例地址。地址按 Android 客户端 `Bill.getImageUrl(key, 2)` 规则生成：图片对象键以 `_hg` 结尾时使用 `!huge`，否则使用 `!webporigin`，并将当前图片 CDN 升级为 HTTPS。仅拼接裸对象键可能无法读取。该规则依赖钱迹客户端及当前 CDN，未来可能变化。

已知边界：超长图片可能被钱迹 CDN 以 `image area too large` 拒绝处理，即使链接生成正确也无法打开。本轮样本在 App 中也无法读取；服务不提供绕过访问限制的原图下载，也不能保证所有长图可用。

图片地址的查询沿用原账单的账号访问控制，但返回后应视为私人资料，不公开传播或发送给无关第三方。客户端访问 CDN 时不应附带 MCP PAT、钱迹登录凭据或 cookie。服务不会为构造图片地址发起额外网络请求。

### 分类与标签的批量写入

批量操作按输入顺序执行，不是远端事务。参数先整体校验；若中途失败，`WRITE_PARTIAL` 消息会给出从 1 开始的 `completed`（已完成）、`unconfirmed`（结果未确认）与 `notAttempted`（尚未执行）序号。已完成项不得重试；未确认项需先查询核对，禁止直接重试整个批次。缓存清理失败时先调用 `refresh_cache`。

分类删除的转移目标不能出现在本批次待删除分类中，`transferTo` 与 `deleteBills=true` 不可同时指定。删除分类会同步受影响账单并失效余额缓存；若同步失败，先用 `refresh_cache` 再核对账单和统计。

分类的 `deleteBills=true` 路径会删除账单，但不回滚资产余额（Android 4.5.4 接口实测）；刷新缓存不会修复该差额。如需回滚余额，先核对范围并通过 `delete_bills` 删除账单，再删除空分类。有子分类时须先处理子分类，服务端会拒绝直接删除父分类。

分类改名和标签局部更新会先读取最新目录，补齐未改动字段再提交；请避免在提交期间从其他客户端同时编辑同一项。删除标签组会将组内标签移到默认组；空标签组暂不显示在 `list_tags` 的分组列表中。

分类移动会先读取当前层级：一级降为二级和二级提升为一级使用层级调整接口，二级分类换父级使用移动接口。非空分类删除必须选择转移或删除其账单，省略两者会被服务端拒绝。账单查询中 `categoryId` 是精确筛选；需要包含子分类时使用 `categoryIds` 和 `includeSubcategories`。


### 工具参数和金额规则

### 调用时需要注意

- 钱迹业务 ID 始终使用十进制字符串，包括 `"-1"` 等特殊值
- `list_bills` 不筛选时传空对象 `{}`，默认每页 20 条，最多 100 条
- `list_books` 和 `list_assets` 可用 `nameKeyword` 按不区分大小写的名称字面子串缩小范围，`list_assets` 默认不返回余额和信用额度，只有明确需要余额或额度时才传 `includeBalances: true`
- 借入或借出详情使用钱迹独立接口 `list_debt_accounts`，`list_assets` 可能包含 type 5 债务记录基础资产条目，但不能替代详细信息，也不要自行聚合两类响应
- `list_bills.remarkKeyword` 按不区分大小写的备注字面子串筛选
- 请求下一页时只传上一页的 `nextCursor`，不要重复传筛选条件或 `limit`
- `bookId: "-1"` 只表示钱迹默认账本，`categoryId` 不接受 `"-1"`
- `create_bills`、`update_bills`和 `delete_bills` 即使只操作一笔也使用单项列表，级联删除在对应 `deletions[]` 项中显式设置 `cascadeRelatedBills: true`
- 批量写入只部分成功时，错误会按输入序号列出逐项结果，成功项已经写入，不得重试
- `set_budget` 必须指定 `bookId`、`period`、`target` 和本位币 `amount`，`target` 为 `{ "kind": "total" }` 或 `{ "kind": "category", "categoryId": "…" }`，0 清除此项额度，不删除账单
- 钱迹预算写入接口替换整个期间的预算列表，服务会先读取最新完整定义、合并单项修改、提交并回读核对其他额度；这不是跨客户端原子操作，请避免在 App 同时改预算，结果未确认时先用 `get_budget` 查询

`money`、`fee` 和 `discount` 均使用币种主单位，不使用分、美分等最小货币单位。

| 输入 | 实际含义 |
|---|---:|
| `CNY 8100` | 8100 元 |
| `USD 63` | 63 美元 |
| `JPY 500` | 500 日元 |

- 普通支出：`money` 对应 APP 主金额输入框，只支持 `discount`，实际扣款为 `money - discount`，收入不支持手续费或优惠
- 转账或信用卡还款：`money` 对应 APP 主金额输入框，`fee` 和 `discount` 不能同时大于 0，手续费包含在 `money` 中，优惠从实际转出金额扣减
- 跨币种写入会使用账号已开启的多币种配置，`get_user_info.baseCurrency` 是当前本位币，账单 `currencyConversion` 是写入时的历史换算，不会按当前价格重算
- 业务金额必须大于 0、不超过 `9,999,999,999.99` 且最多两位小数，手续费和优惠不能大于 `money`
- 账号需要迁移新版报销时，首次 `reimburse_bills` 会提示迁移影响。未启用服务端持久回执时，向用户说明“迁移后旧版本将不能继续使用报销”并取得明确同意后，使用相同业务参数并将 `confirmReimbursementUpgrade` 设为 `true` 重试。服务器只会在钱迹明确要求时迁移并重试一次
- 启用持久回执时，首次迁移提示可能留下 `uncertain` 并阻止继续写入。先查原回执与实际账目，记录阻塞。同一 `requestId` 改参数会冲突，不能换号或删回执继续迁移



### 数据同步

- 首次查询账单时，服务会自动同步钱迹数据
- 后续查询优先读取本地缓存，跨设备修改后可调用 `refresh_cache`
- 写操作会在远端成功后同步确认

> [!IMPORTANT]
> 写后确认失败不表示远端已经回滚，账单或目录按提示调用 `refresh_cache` 后核对，预算直接调用 `get_budget` 回读；不要盲目重复写入。

### 写入限制

桥接层不再设置每日写入次数上限；钱迹服务端的业务限制和错误仍正常返回。有效 VIP 每次最多使用 8 个标签，非 VIP 或过期 VIP 最多 1 个。

旧数据库的写入计数列保留以兼容旧版本，但新版本不读取它来限制写入，也不再更新计数。`get_user_info` 不再返回 `dailyWrite*` 字段；调用方不要把这些字段缺失解释为额度用尽。


### 稳定请求号、附件和对象版本

启用私人 `QIANJI_MCP_OPERATIONS_ROOT` 后，为每个业务请求保留一个 `requestId`。同一业务重发必须沿用原号；成功回执直接返回，不再次写入。`get_operation_status` 返回 pending/uncertain 时先查实际状态，不能换号、删除回执或更换目录绕过门禁。未知操作不自动解锁；下述专用复核只处理符合证据条件的已结束调用。回执只协调单机共享目录，不能阻止官方 App 同时编辑。

修改或关联已有账单要传 `get_bills` 返回的 `fingerprint`，对应 `expectedBills: [{billId, hash}]`。目录、周期、借贷和分期分别使用查询返回的 `version` 作为 `expectedVersion`；过期版本在写入前拒绝。

`upload_bill_image` 接受最多 8 MiB、2400 万像素的单帧 PNG/JPEG 标准 Base64。存储回执、文件哈希和解码像素分别核验，只有 `pixelsVerified=true` 的本账号已确认上传回执可以用于 `set_bill_images`。默认追加保留旧图，替换需明确指定，最多 6 张，不自动丢弃超出的旧图；不修改日期、金额、备注、分类等其他字段。

`manage_catalog_object` 可创建账本、CNY 现金/信用账户、修改基础资料和显示状态、标签组改名；删除只接受自有空账本或零余额普通资产，检查账单、周期、分期及借贷/共享额度引用。修改现有资产保留余额和信用设置，不能用普通资料编辑代替余额调整。

`create_repeat_task` 补充收支、待报销、转账与还款的固定金额周期，支持日、周、月、年、法定工作日及间隔天数；`update_repeat_task` 仅修改金额、手续费、备注、时刻及频率，保留任务身份和原账户/账本关联。未来自动执行结果需届时查询，不以设置保存成功推断未来账单一定正确。

### 导出与时区

`export_bills` 返回 CSV 或 JSON 摘要内容，最多 10000 行，沿完整分页边界停止。只有 `complete=true` 才表示该筛选范围已经读完；否则用 `nextCursor` 续导，续导不混传筛选条件。CSV 防止文本公式执行并保护长整数 ID，JSON 保留结构。导出不包含附件二进制，不写任意服务器路径。

`get_time_zone` / `set_time_zone` 管理当前账号在本服务的 IANA 时区，默认 Asia/Shanghai，多个 PAT 共用账号设置。报表和预算按当地自然日分桶，夏令时不按固定 86400 秒累加。返回的 `timezoneOffsetSeconds` 是期间起点偏移，期间内可能变化；历史 Unix 秒不转换，不修改钱迹 App 设置或已有周期的时刻。

### 借贷与分期

`get_debt_details` 返回借贷详情及版本，`manage_debt` 使用原生本金/归还/利息类型，创建、追加、归还和零本金结清分别核验双方余额及本金/累计还款。当前要求正常自有 CNY 资金账户，新建借贷还要求账号本位币为 CNY；原生详情省略币种时按已查询的本位币解析，起始资金账户以本金账单关系核验。新增本金不夹带利息，纯利息归还可以本金为零。

`list_installments` 返回分期设置和版本，`manage_installment` 创建未来起始的独立 CNY 信用分期、修改统计开关或删除未产生账单的设置。本金、总手续费、期数、费用分配和分币余数位置必须明确。当前不回补历史分期、不提前还款、不修改已生成分期账单；配置成功只证明当前回读通过。


`manage_debt.deleteSettled` 只永久删除已结清、无利息、无附件且各资金账户本金净流动为零的循环，必须提供全部本金账单 ID 和逐笔指纹。实测服务端会退回还款金额，却不回退借入/借出本金，与 APK 旧提示不同。返回 `cashBalanceEffects` 列出已核验的余额变化，不会自动调整余额；需要恢复时须有独立依据和明确授权，使用条件式恢复工具，不得用余额修改掩盖未知差额。

### 已结束操作的限定复核

以下工具不重发原写入，也不删除或覆盖原回执；成功复核只关闭原请求的待核实状态。原号再次调用仍返回原失败回执。

- `verify_rejected_bill_operation`：只接受上游明确拒绝的附件、普通账单或转账修改，原参数及全部账单指纹一致且刷新后未变，记录 `notExecuted`。
- `verify_future_repeat_creation`：只接受创建接口已返回但确认失败的未来任务，唯一匹配原参数、创建时间窗、所有者且未生成账单，记录 `reviewed`。
- `verify_debt_creation`：匹配原创建参数、时间窗、借贷本金及唯一的起始账单，另需按写前余额和请求本金独立计算的资金余额。不能直接照抄当前余额。
- `verify_debt_deletion`：匹配原删除参数及指纹，刷新确认借贷、全部本金账单和关联均已消失，并独立核对全部受影响资金余额；不自动修复余额。

这些入口不是通用解锁工具，不处理超时、仍执行中的请求或未知的部分成功；借贷追加、还款、结清以及周期编辑失败仍须停止并调查。跨客户端并发修改也不受本机回执保护。

清空附件或删除账单不等于物理删除图片存储中的文件；当前没有云端图片物理删除工具。
