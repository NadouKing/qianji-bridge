## 功能与边界

| 项目 | 本轮实现 | 验收重点 |
|---|---|---|
| 持久回执 | UID 隔离的私人 SQLite 回执、稳定请求号、只读状态查询、原账单版本检查 | 重连/重启不重发，同号异参拒绝，部分成功和不确定结果停止后续写入 |
| 图片 | PNG/JPEG 解码、上传存储回执、CDN 文件/像素核验、追加/显式替换附件 | 旧图和其他账单字段保留，不把已上传但不可读误当未上传 |
| 目录 | 账本、CNY 现金及信用资产创建，基础资料/显示状态，标签组改名，空对象删除 | 版本冲突拒绝，余额和信用参数保留，删除检查账单/周期/分期/借贷及共享额度引用 |
| 周期 | 固定收支、待报销、转账/还款，六种周期；编辑金额/费用/备注/时间/频率 | 保留身份和历史，核验新账单归属及余额；不修改原账户/账本关联 |
| 导出 | CSV/JSON 摘要、分页完整性、续导游标、CSV 公式与长 ID 保护 | 不漏页、不重复，不把截断结果标为完整，不导出图片二进制 |
| 时区 | 账号级 IANA 设置、自然日统计/预算、信用还款日期与请求偏移 | 23/25 小时自然日、午夜跳时、跨月、并发账号隔离，不改历史 Unix 秒 |
| 借贷 | 原生借入/借出、追加本金、本金与独立利息归还、零本金结清及限定的已结清循环删除 | 双方余额、本金累计/已还累计、原生账单关系、删除范围及服务端还款退回效应 |
| 分期 | 未来起始的独立 CNY 信用分期、统计开关、删除未执行设置 | 分币余数及费用分配、版本冲突、原账单与余额不变 |

借贷与分期暂不覆盖跨币种、历史分期回补、提前还款、已生成分期账单编辑。目录创建尚不覆盖所有资产子类型或共享信用额度创建。周期和分期设置回读不等于未来自动执行已经验证。

## 验证方法

离线验证包括真实 MCP HTTP 传输的工具 Schema 与回执行为、签名请求的模拟 HTTP 协议、SQLite 迁移及重复重开、子进程中断、三进程同号争用、原字段保护、异常回读与独立金额核验。测试数据全部为合成数据。

完整回归以不同顺序复测，另跑类型检查和 Python 流水解析测试：

```sh
bun test --randomize --seed 1101
bun test --randomize --seed 2202
bun test --randomize --seed 3303
bun run typecheck
python -m unittest discover -s test -p '*_test.py'
```

最终离线回归：三个随机顺序各 **241 通过、1 跳过、0 失败**（共 242 项），类型检查通过，Python 解析测试 **5 通过**。

实际验收由用户单独登录隔离本机服务，不读取或复用生产服务凭据。PostgreSQL/MySQL 未配置专用测试数据库，实库测试跳过；Linux 容器也未实测。SQLite 回退检查覆盖旧字段保留与具名读写兼容，不宣称已运行旧版本服务器。

真实验收使用新建的专用账本、资产、分类和任务，通过注册的 MCP 工具执行。每笔保留稳定请求号和私人结果，按创建、回读、编辑、回读、重连后同号查询/重发、清理的顺序进行；出现未知结果停止写入并核查。已有真实账单不作为测试对象，原始响应、凭据、账单与运行日志不进入 Git 或 PR。

## 实际接口验收结果

在用户明确授权的新建测试对象内完成：

- 三轮收支创建、修改、退款、含手续费转账、导出及删除，每轮余额回到起点。
- 两张合成 PNG 上传及像素回读，追加保留旧图、重复追加去重、显式清空和账单删除。
- 周转账、工作日支出、间隔日收入各一轮，每轮三次编辑、暂停和删除；历史账单及余额未受这些任务修改影响。
- 三种手续费分配的未来分期，各三次统计开关修改后删除，信用余额保持不变。
- 三轮账本/现金/信用资料和显示状态修改、纽约/上海时区往返；标签组三次改名后删除。
- 三轮逐页导出，每页一条，核对完整集合及无重复；已删除账单的创建请求重复提交仍只返回原回执，没有重建。
- 借入、借出各三轮，验证创建、追加本金、归还、结清及删除。删除后的服务端还款退回金额经独立计算，通过既有条件式恢复工具恢复测试现金余额，并重新核对。
- 每项创建多次同号重放，另验证隔离服务重启后回执仍有效。已结束异常通过限定复核记录关闭，最终没有 pending/uncertain。

最终全量刷新确认：测试账本、三项普通测试资产、两个分类、一个标签组、三项周期、三项分期、六项借贷和所有测试账单均已删除；测试服务已停止，生产服务未改动。图片已解除关联且对应账单已删除，但未确认两张合成上传文件在图片存储中的物理删除；当前没有此工具。私人回执和审计留在仓库外，不公开。

实测修正了附件更新的原生 status/展示字段、周期结束条件与空数组规范化、借贷本位币及起始资金关联、资产删除关联检查，以及借贷删除的实际余额效应。协议同时核对本机官方 Android APK 的资产/分期 API 与提示；服务端实测与旧提示冲突时明确记录差异。

本轮真实写入不覆盖借贷利息、跨币种借贷、提前还款、已执行分期，以及所有周期类型/账单类型组合。利息金额与关系、日/月/年规则及异常边界有离线测试；未来自动执行未等待到期验证。不得将受限实测表述成全部接口分支均已验证。

## 提交顺序与合并门槛

1. 上游边界修补和配额兼容
2. 持久请求回执与状态查询
3. 图片上传和附件关联
4. 目录管理、周期编辑与导出
5. 多时区、原生借贷和未来分期

代码按上述依赖拆分提交。PR 分为上游兼容/配额和依赖它的功能升级两部分；功能升级内保留分项提交，并将真实验收发现的跨模块修正一并交付。提交 PR 不包含合并、生产部署或重启生产服务。尚未通过的接口功能保持待验收，不用离线测试代替实测结论。

持久回执不能提供钱迹服务器端的全局 exactly-once 保证，不能阻止 App 或其他设备并发修改。目前 pending/uncertain 不自动解锁，也不按时间过期；限定的已结束操作可通过专用复核关闭，保留原失败回执，其余情况继续停止写入。不删除回执绕过门禁。完整行为见[部署说明](deployment.md)和[使用说明](usage.md)。
